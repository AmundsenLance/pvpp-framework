Productive Value–Productive Power

A general framework for reasoning about productive capability, interaction, viability, recovery, future reachability, and consequential action — from human and institutional systems to autonomous AI agents.

Understand the framework Explore AI-agent governance Runtime repository

PV-PP separates Productive Value (PV) — productive transfers realized through interaction — from Productive Power (PP) — the structured capability to produce, obtain, transform, coordinate, or otherwise realize productive outcomes. It then asks a broader governance question: not merely whether an action is attractive or technically possible, but whether the successor state it creates remains admissible, viable, recoverable, and authorized.

The framework

A theory of productive systems — not a one-number score

PV-PP was developed to analyze systems in which productive capability, value, perception, constraints, recovery, and future possibilities interact across multiple domains. It does not assume that every relevant condition can be collapsed into a single compensatory metric.

PV

Productive Value

Goods, services, information, currency, and other productive transfers realized through interaction. PV concerns what moves, is exchanged, or is realized between productive entities.

PP

Productive Power

The actual structured capability of an entity to produce, obtain, transform, coordinate, or otherwise realize productive outcomes. PP is multidomain and need not share a common unit.

PPP

Perceived Productive Power

The perceived or projected productive capability used in decision governance. Because decisions act on represented rather than omniscient state, the distinction between actual PP and perceived state matters.

Important ontology boundary: a credential, tool, dollar, permission, network route, relationship, memory record, or piece of infrastructure is not automatically Productive Power. Such objects may be resources, stored state, access conditions, authority, configuration, affordances, or control relationships. They count as PP only when the application can justify the productive capability they instantiate.
Why non-scalar?

Some conditions govern before ranking begins

A candidate can be productive and still be inadmissible. Missing authority, invalid evidence, loss of recovery, a failed viability threshold, an invalid state transition, or a hard upper authorization boundary need not be tradable against gains somewhere else.

Preserve structure

PV-PP keeps distinct domains and decision authorities distinct long enough to determine what actually governs the decision. Feasibility, framing, adequacy, authorization, and selection are not treated as synonyms.

Govern successor states

The question is not only “may this action occur?” but “what productive and control state exists if it succeeds, and what future paths does that state make reachable?”

A central security and viability construct

The two-sided productive corridor

PV-PP can govern both too little productive capability and too much authorized capability. The two sides are complementary but need not be mathematically symmetric.

Lower boundary: viability and recovery

A productive system may need to retain minimum capability in critical domains. Recovery-necessary controller capacity can remain governing even while currently healthy, so an action can be rejected if it destroys the ability to interrupt, revoke, isolate, redirect, restore, or otherwise recover the system.

⇄

Upper boundary: authorization and admissibility

Some productive capability can remain useful and technically feasible while becoming unauthorized when it becomes too extensive, persistent, independent, delegated, or difficult to reverse. Hard Constraints can impose justified upper authorization ceilings.

The result is a governed interaction corridor: enough capability to perform legitimate productive work and preserve recovery, but not unlimited authority to accumulate or exercise additional productive power.

Autonomous-agent governance

AI agents are productive systems

Persistent autonomous agents can acquire information, use tools and resources, coordinate, learn, obtain access, form dependencies, create persistent effects, and change what actions become possible later. That makes their security problem larger than isolated permission checks.

Capability-state governance

PV-PP can represent how an authorized action changes actual productive capability, reachable transformations, dependencies, and the future interaction corridor.

Controller recovery

Agent capability is considered together with independently retained controller capability. A below-ceiling action can still be rejected if it compromises the controller’s recovery corridor.

Safer productive substitution

If a proposed means is inadmissible, governance can consider another productive path: narrower scope, different tool, staged authority, controlled service, additional review, or another acceptable substitute.

The OpenAI–Hugging Face incident as a counterfactual case

A completed incident analysis originally tested PV-PP against the July 2026 OpenAI–Hugging Face autonomous-agent security incident using an earlier runtime generation. The subsequent Version 2 framework and v0.131 runtime provide substantially more operational governance machinery. The resulting counterfactual does not claim that PV-PP would necessarily have prevented the historical incident. It asks what current PV-PP could have governed if relevant evidence and consequential primitives had been integrated into its decision boundary.

Credentials and production executionCredentials are not automatically PP, but their consequences can change authenticated access, authority, affordances, and exercisable capability. Consequential use can be denied when the resulting transition fails canonical governance.
Claim boundary: PV-PP does not replace identity management, Zero Trust, sandboxing, cryptography, network controls, telemetry, endpoint security, or incident response. Those systems provide observation and enforcement. PV-PP can serve as a productive-state governance layer deciding whether the state an agent is about to create remains viable, recoverable, and authorized.

Authority-bound execution

Native consequential execution is not authorized merely because a host can construct an execution context. The v0.131 runtime binds native call-through to runtime-issued authority derived from the governed decision lineage and consumes that authority as a single-use execution authorization.

Controlled governance re-entry

When evidence, structure, capability, configuration, provenance, or dependencies materially change, the runtime can invalidate dependent artifacts and return to the earliest canonical stage whose authority is no longer valid rather than silently continuing with stale governance.

The frozen v0.131 scope is synchronous. Asynchronous, concurrent, and distributed execution and true mid-flight cancellation are not claims of the current reference runtime.

Research program

What has been tested

PV-PP is an active research program. Its claims have been developed through formal reduction work, cross-domain ontology and architecture studies, runtime implementation and regression testing, simulation benchmarks, application ports, and adversarial autonomous-agent security analysis.

Non-scalar structure

Formal work tests when multidomain PV-PP decisions can and cannot be reduced to scalar forms while preserving the governing structure.

Cross-domain portability

Framework and runtime work tests whether the same decision architecture can travel across materially different productive systems without hiding application decisions inside adapters.

Agent security

Security research has tested upper capability bounds, controller recovery, evidence authority, structural incompleteness, dynamic affordances, capability formation, and consequential execution.

Boundaries matter

What PV-PP is not

  • It is not a utility-maximization model or universal one-score ranking system.
  • It is not limited to economics, markets, pricing, or monetary exchange.
  • It is not an AI-only framework; autonomous-agent governance is one major application of a broader productive-systems architecture.
  • It is not a replacement for domain models, security sensors, enforcement mechanisms, or trustworthy external evidence.
  • It is an active research framework and open implementation project, not a settled mainstream academic school.

Project status

A framework, a runtime, and an expanding application program

The stable idea across the PV-PP research program is straightforward: productive decisions should be evaluated in terms of the capabilities, transfers, constraints, recovery conditions, and future states they create — without assuming that every governing condition can be traded against every other one.

For first-time readers, this page is intended to be the public map. The framework repository contains the theory and canonical explanatory materials; the runtime repository contains the executable reference implementation; application papers and examples show how the architecture behaves in particular domains.
